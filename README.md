# FluxNav · 个人资源工作台

Local-first AI Bookmark Workspace。保留编辑式起始页，提供三栏资源管理、收藏集、标签、收藏、置顶、归档、回收站、批量操作、全局命令面板、四种主题、JSON/浏览器 HTML 导入导出。

- [GitHub Pages](https://weepwood.github.io/fluxnav/)
- [Netlify](https://fluxnav.netlify.app)

## 开发

Node.js 22；运行 npm ci、npm run dev。npm run check 执行 TypeScript 和领域逻辑测试。npm run build 生成支持离线的 Web 站点，npm run build:portable 生成单文件 HTML（离线分发仍依赖浏览器存储能力）。GitHub Actions 的日常 PR 和 main 仅执行快速检查及 Web 构建，main 成功后自动部署 GitHub Pages；不自动创建 Release。正式版本由独立的手动工作流验证和发布。

## 数据与迁移

自动迁移旧 LocalStorage 书签到 IndexedDB；原始书签保留供导出，凭据不再持久化。若 IndexedDB 不可用，降级到 LocalStorage 或内存并提示。导入前预览，按规范化 URL 去重；JSON 导出包含回收站。默认不请求第三方图标或字体。不同域名、浏览器配置文件及沙箱的存储相互独立。

## AI

设置兼容 OpenAI Chat Completions 的服务地址、模型和本次会话 API Key。服务须允许浏览器 CORS。可保存多个非敏感服务配置。AI 推断标题与网址、批量添加、分类及检索仅生成建议，须确认才写入。分类和检索每批最多 50 条，发送前明确确认，仅发送 ID、标题、网站来源、标签及收藏集，不发送完整 URL 路径、查询、片段、备注、描述；不读取真实网页内容、不保证 URL 正确。

## 同步

GitHub Secret Gist 或自定义 JSON 服务。Gist 不是严格私密存储，可设置独立口令，通过 PBKDF2-SHA256（600,000 次）派生 AES-256-GCM 密钥，在浏览器内加密后再同步。口令不持久化，丢失不可恢复；使用过明文同步的旧 Gist 历史版本可能仍包含原始数据。同步前快照和合并预览，按 ID、修改时间和删除标记确定版本。Gist 推送前检查远端版本，但非原子条件更新，极端并发仍有竞态。自定义服务须支持 Bearer GET/PUT、CORS、ETag/If-Match，且预先创建合法 JSON 资源。Token/API Key 只在当前页面内存中。不要输入权限过大的 Token。

## 扩展与离线

extension/ 为 Chrome/Edge MV3 捕获扩展，加载解压目录即可使用；点击图标后在 FluxNav 确认保存。PWA 缓存应用壳，不缓存 API 请求；需要首次联网加载。独立 HTML 不注册 Service Worker。

## 限制

不提供任意网页内容抓取、自动失效链接检查、实时多设备同步或商店上架。浏览器跨域限制下，相关能力需要独立服务。同步采用整条记录版本合并而非字段级 CRDT。

## 1.1 体验改进

支持相关度排序、标题英文单字符拼写容错、首页收藏筛选和分批展示。管理页面支持批量移动收藏集、追加标签、撤销上一次资源更新、复制网址、双击打开和本地保存状态。导入 JSON 可选择仅添加新网址或按 ID 与版本合并完整备份（包括删除记录）；后者可能更新已有记录。浏览器 HTML 导出保留收藏集名称。

性能策略：按不可变书签缓存搜索投影、延迟搜索更新、限制每次渲染条目数、减少无变化写入。IndexedDB 仍采用整体数据记录存储，尚未实现逐条持久化和全文倒排索引。

## 1.2 工作台细化

在设置中可调整首页布局、列表密度和每页数量；宽屏桌面支持鼠标或键盘调整分栏。收藏集重命名会更新未删除记录（包括归档），重复资源可逐组确认合并：保留指定记录的标题及网址，汇总标签、备注、描述、访问统计，其余记录移入回收站。规范化网址忽略 URL 片段，合并前请核对页面章节。长文本与标签仍受字段长度限制。配置仅保存在当前浏览器。

## CI/CD 与正式发布

日常迭代：PR 运行 `npm run check:quick`（类型检查、核心单元测试）以及 Web 构建；合并 main 后自动部署 Pages。跳过 E2E、压力测试、安全审计、便携版与扩展打包，不因版本号变化自动发布 Release。

正式版本节点：在 main 上准备好版本号（package.json、package-lock.json、extension/manifest.json）与 CHANGELOG.md，然后打开 Actions → 正式版本完整验证与发布 → Run workflow。默认仅完整验证并生成分发产物；勾选 publish 后，全部测试通过才创建对应提交的 Git tag 与 GitHub Release。既有版本或标签不会被覆盖。也可使用 `gh workflow run release.yml --ref main -f publish=true`。正式发布工作流不重复部署 Pages。

本地命令：`npm run check:quick` 用于日常检查；`npm run check` 包含完整单元测试和压力测试；浏览器 E2E 单独运行。正式发布工作流可以随时手动用于专项验证，不必等到新版本。

## 1.3 开发里程碑

收藏集通过 ` / ` 表示层级，如 `设计 / 图标`，父级显示全部子级书签，重命名会更新整棵子树。HTML 导出保留实际嵌套目录。管理页选择手动排序后，可在同一置顶分组内通过拖动手柄或快捷菜单调整顺序；也可直接拖动书签到收藏集。右键或更多按钮打开快捷操作菜单。排序保存在书签记录中并参与 JSON 备份及同步；旧版数据无需迁移。日常开发版本只部署 Pages，不自动创建 Release。

网站图标默认仅本地生成字母占位图标。可在外观设置选择直接请求 HTTPS 网站根目录的 `/favicon.ico`，不经过第三方代理，不发送 Referer；远端站点仍能看到请求信息。使用浏览器 HTTP 缓存及本次会话失败记录，无法保证所有网站都有图标，也不保证永久离线缓存。

## 1.4 性能和安全导入

大规模候选列表（至少 2,000 条）使用内联 Web Worker 搜索；较小列表或 Worker 不可用时使用主线程缓存搜索。分页列表使用 CSS content-visibility 延迟离屏绘制，并保留原生焦点及拖拽操作；不是完全 DOM 虚拟化。IndexedDB 数据库升级到 v2，将书签迁移到独立对象存储，保留旧 `data/library` 作为迁移时备份。保存只写入变化记录，跨标签页修订号变化后重新读取。迁移与写入使用事务；旧标签页可能阻止升级，请关闭旧页面再刷新。旧版客户端不能读取升级后的数据库，请先导出再降级。跨标签页仍非实时同步。

导入限制单文件 30 MB、最多 100,000 条、仅 HTTP(S) 合法网址；异常条目独立跳过，缺失标题、部分标签格式等可修复。可选编码（UTF-8/UTF-16 BOM、GB18030、Big5、Shift-JIS、Windows-1252）。默认只追加新网址，预览文件内重复、现有重复、无效和修复数量并可下载异常报告；完整有效的 FluxNav JSON 才允许按 ID/版本恢复（包括删除标记），需显式确认。导入不访问书签网站，HTML 在惰性模板中解析。恢复不是数字签名认证，仍只应使用信任的备份。256 KiB 及以上文件优先在 Worker 内解码与解析 JSON；HTML DOM 解析仍在主线程。Worker 不可用时回退。涉及 storage.ts 的 PR 单独执行轻量 IndexedDB 模拟迁移专项验证，不安装 Chromium；正式发布也执行该专项验证。

## 1.5 AI 与标签整理

AI 工作台支持按选中、未分类、无标签及本地搜索过滤资源，50 条一批，逐批明确确认发送。返回内容作为不可信输入：新增建议通过书签导入校验，忽略 AI 指定的 ID、删除标记和访问数据；整理建议仅允许标签与收藏集，预览变化，可追加或替换标签，应用时跳过已更新/归档/删除记录。批量分类可撤销。标签管理可在本地归并大小写及全角等变体或自定义标签（含归档，不含回收站）。语义检索仅检索当前批次，不是跨库向量索引。

导入预览可搜索、分页查看并排除条目，重复记录仍按原规则处理。新增和恢复操作支持 30 秒内整批撤销；新条目撤销时写入回收站标记而非物理删除，已发生后续修改的记录跳过。撤销仅本次会话的最近一次操作，不是持久历史。

## 1.6 界面设计专项

统一四套主题的视觉令牌、选中与焦点状态、控件圆角及间距；重做起始页的集中式搜索及书签区域、工作台标题层级/视图切换/资源条目与详情、带导航和主题预览的设置面板。保留原有布局偏好、数据格式、拖动与快捷操作，不新增外部字体依赖。后续版本优先视觉与交互迭代，浏览器扩展等新增功能暂缓。

## 1.7 工作台视觉专项

工作台以独立滚动的导航、资源列表、检查器为基础；桌面侧栏可收窄为图标栏，详情开启时预留宽度，未选择资源时显示空状态。工具栏与分页固定，标签及收藏集可折叠，导航显示数量；详情的元数据、内容与操作区分离。平板与手机使用浮层详情，手机侧栏为抽屉。保留原有栏宽偏好、拖拽排序、批量操作及数据逻辑。

工作台视觉专项 `workspace-visual.yml` 仅在专项脚本/工作流本身发生变化或手动触发时运行，不加入日常快速 CI。使用独立测试数据及中文字体环境，以 96 条演示数据检查三栏几何、固定工具栏、图标栏、网格、深色与移动端抽屉，上传截图供人工复核。

## 1.8 首页设计专项

首页使用独立视觉令牌、重做书签列表和磁贴、支持即时布局切换、置顶分组与标签计数，直接添加书签。设置中的「首页」分类支持纯色、纸面、点阵及柔和色晕（本地 CSS，无外部图片请求）、强调色、标题、副标题、密度、宽度、域名与置顶分组显示。旧偏好自动补齐默认值，重置首页不影响工作台或网站图标隐私设置。背景仅提供本地样式预设，不读取外部或上传壁纸。

首页视觉专项仅在 `tests/home-visual.mjs` 或对应工作流修改及手动触发时运行，检查布局、设置持久化、搜索和手机宽度，并生成截图。日常 CI 仍使用快速检查。

## 1.9 交互与动效专项

使用独立 `styles/motion.css` 令牌（100/120/160/220ms），固定工作台网格轨道数量和导航图标位置，支持快速反向切换，拖动分隔栏时停用过渡。移动导航及详情使用平移，设置分类使用轻微淡入，原生 dialog 进入/用户关闭时使用短动画（提交/跳转与忙碌取消不延迟）；保持键盘焦点与原生模态语义。手动排序在列表使用上下边界、网格使用左右边界；系统减少动态效果偏好全局禁用动画与过渡。未引入动画库。

## 1.10 公共组件与设计规范

`styles/tokens.css` 集中维护主题、语义颜色、字体、尺寸、圆角和动效；`styles/controls.css` 为共享控件基础，保留旧 class 兼容；`components/ui.tsx` 提供 Button、IconButton、Input、Textarea、Select、Checkbox、SearchField、Segmented、Tag。首页、工作台、命令搜索、编辑器、外观设置及详情的高频控件优先迁移，剩余旧页面样式逐步治理。访问 `#/design`（设置→外观→组件与设计规范）可使用真实组件进行四主题隔离预览，不写入用户配置。弹窗复用现有 Dialog。未新增依赖。

设计系统专项工作流仅在其脚本或工作流变更及手动触发时运行。本轮同时运行既有首页、工作台和动效专项以验证共享样式迁移；不加入普通快速 CI。

## 1.11 响应式体验专项

工作台断点：≤650px 手机抽屉、651–1000px 平板浮层、1001–1199px 固定三栏、≥1200px 自定义栏宽、≥1600px 宽屏布局。统一 JS 模式与 CSS 断点约定（`responsive.ts`、`responsive.css`），跨断点关闭遮挡详情，保持桌面栏宽偏好；手机导航高度不受旧样式限制，浮层背景资源区不可交互，批量操作横向滚动，短窗口与触控设备单独优化。触屏不显示拖拽手柄，仍可通过菜单上移/下移（手动排序）或批量移动收藏集。
